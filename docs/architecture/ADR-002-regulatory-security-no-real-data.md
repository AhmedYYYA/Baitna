# بيتنا | BAITNA — قرار البوابات القانونية والأمنية للمشاريع السكنية
**التاريخ:** 18 نوفمبر 2026 · **الحالة:** تصميم واختبارات أولية، **NO REAL DATA** · **لا يُدمج في التشغيل الإنتاجي**
 
## 1. اعتماد المطابقة حسب المشروع
لا يُنشئ بيتنا نصاً يدعي المطابقة للقانون اعتماداً على الإمارة فقط. تُسجل الحقول الآتية لكل مشروع في البيئة الخاصة: Permanent Home ID، الإمارة، المدينة/المنطقة، موقع القطعة وأحكام تخصيصها، سلطة الترخيص المختصة، طبيعة الأعمال (إنشاء/إضافة/تجديد/صيانة)، المخططات المتاحة، وحالة الأعمال الخاصة (مسبح، مصعد، طاقة شمسية، ملحق).

## 2. نماذج الطرح وفق القوانين المعمول بها
ملف متطلبات المالك (ORB) هو المصدر الموحد؛ وثائق طلب معلومات (RFI) وطلب تقديم عروض (RFP) وطلب عروض أسعار (RFQ) تُولد بإصدارات مستقلة. يضاف إلى الوثيقة **فقط البند التنظيمي الذي راجع المختصون انطباقه**؛ ما لم يُتحقق منه يظهر كمرشح للمراجعة، وليس حكماً قانونياً. لا يصبح اختيار عرض عقداً نافذاً تلقائياً؛ والميزانية خاصة افتراضياً.
 
## 3. الأساس البرمجي المؤهل للمراجعة
أُعدّت حزمة مصدر مستقلة خارج GitHub Pages تشمل:
- سجل 17 مصدراً حكومياً و28 حالة مراجعة مرشحة (7 إمارات × 4 أنواع مشاريع).
- محرك تقييم سياق المشروع وتوليد مسودات مع إثبات المصدر وتحذير عدم الاعتماد.
- مخطط PostgreSQL من 9 جداول، بمعرّف مسكن دائم، وفصل عضوية المسكن عن عضوية المشروع، و`ENABLE/FORCE ROW LEVEL SECURITY` وسياسات المنع الافتراضي والنسخ غير القابلة للتحرير.
- تحقق OIDC مستهدف بواسطة JOSE وJWKS من هوية مصدِّر الرمز والجمهور والصلاحية؛ لم يُربط بحساب UAE PASS فعلي. يتطلب [تأهيل مقدم خدمة](https://docs.uaepass.ae/getting-onboarded-with-uae-pass/onboarding-process-for-uae-pass-service-providers/initiation-phase).
- API خاص يعمل على `127.0.0.1` فقط، ويُرفض تشغيله من دون إعداد هوية وقاعدة بيانات وتمرير بوابات الترحيل، ويمنع حفظ البيانات افتراضياً.
 
**لا توجد أي بيانات إنتاجية في هذه الحزمة.** الشيفرة البرمجية الكاملة محفوظة في حزمة تنزيل مصاحبة للمحادثة، ولم تُنشر كخادم عبر المستودع العام. يجب إيداعها في مستودع تطوير خاص ومراجعتها قبل التنفيذ.
 
## 4. دليل الاختبار والحواجز
- **32/32** اختبار Node للسياسات والمطابقة ومنع الاستقبال والطلبات مجهولة الهوية ووظائف المحاكاة، نجحت في البيئة الحالية.
- **10/10** اختبارات MVP المحلي السابق (SQLite) نجحت؛ ليست PostgreSQL.
- حاولنا اختبار Chromium عبر Playwright فعلياً؛ مُنع الاتصال عبر `ERR_BLOCKED_BY_ADMINISTRATOR`، ولذلك **اختبار المتصفح وSafari/iPad غير معتمد**.
- **لم يُنفذ** الترحيل على PostgreSQL، أو اختبار RLS متعدد الحسابات على DB حقيقية، أو تسجيل مزوّد OIDC، أو ربط UAE PASS، أو اختبار اختراق مستقل.
 
### شروط واجبة قبل أول بيانات حقيقية
- شهادة اعتماد مصدر وقاعدة لكل إمارة/منطقة ونوع مشروع، ومراجعة قانونية وهندسية منفصلة.
- هوية فعلية عبر موفّر موثوق واستكمال اتفاق التأهيل وسيناريوهات الدخول والخروج والإلغاء.
- ترحيلات PostgreSQL صحيحة واختبارات عزل المستخدمين والمقاولين والسجلات وتجارب النسخ الاحتياطي والاستعادة.
- تخزين خاص ومشفّر للملفات، وسياسة احتفاظ وحذف واستجابة للحوادث وفق [إطار حماية البيانات الشخصية الاتحادي](https://u.ae/ar/about-the-uae/digital-uae/data/data-protection-laws).
- اختبارات متصفحات فعلية، واختبارات أمنية مستقلة على نمط [OWASP API Security](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/)، واعتماد إصدار خطّي من المسؤولين.
 
**قرار الإطلاق:** `NO_REAL_DATA`. لا ترفع معلومات مواطنين أو عقود أو أرقام هوية أو مستندات ملكية إلى موقع GitHub Pages أو نماذج محاكاة حتى اكتمال جميع البوابات.
